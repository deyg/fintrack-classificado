## Regras implementadas

- RN02: `categoryId >= 1` (`account.category.required`).
- RN03: despesa exige classificador (`account.classifier.required`).
- RN04: receita não admite classificador (`account.classifier.not_allowed`).
- Classificador ou natureza fora do enum → `account.classifier.invalid` / `category.nature.invalid`.
- Nome: aparado, 1–100 caracteres (`account.name.required`, `account.name.too_long`).
- A natureza é um parâmetro, resolvida pelo caso de uso (Application) via repositório de categorias; o Domain não conhece repositório (aceite do passo). A verificação de existência da categoria é de ACC-002/ACC-003.
- Status: conta nasce ativa; `Activate`/`Deactivate` preservam os demais dados.

## Premissas a confirmar

- Ativar/desativar é **idempotente** (sem erro). O contrato (`ChangeAccountStatusRequest`) não define erro para repetição, então não inventei um 409.
- Alteração de nome/categoria/classificador (`PATCH`) será modelada em ACC-006, junto com DEC-RN-002 (parte conta), ainda pendente.
