## Regras e códigos

- Atualização parcial; `Transaction.Change` atômico com os valores mesclados.
- Corpo sem campos (`{}`) => 422 (chave `body`, `minProperties: 1`); `amount`/`accountId`/`realizedAt` com `null` explícito são tratados como ausentes.
- `description: null` limpa; ausente mantém; texto é aparado.
- Troca de `accountId`: conta inexistente => 422 (`accountId`); conta inativa => 409 (RN09). Manter a mesma conta não exige conta ativa (permite corrigir lançamento de conta desativada).
- `realizedAt` futuro => 422 (RN07, `TimeProvider`).
- 404: lançamento inexistente. 400: id inválido, JSON malformado/tipo errado, propriedade desconhecida, corpo vazio (DEC-ERR-005).

## Pendências e riscos

- Interpretação de `null` explícito em campos não anuláveis como "ausente" segue o padrão de `updateAccount`; o contrato não define.
- Corrida de edição concorrente não é serializada (sem concorrência otimista).
